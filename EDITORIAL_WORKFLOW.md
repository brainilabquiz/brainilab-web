# BrainiLab Learn

The public library is `/learn/`. Reviewed articles live in `content/articles/*.json`;
HTML, the library, home previews and sitemap entries are generated by
`python3 tools/build-editorial.py` (also included in `npm run build`). On Windows,
use `python` if that is the installed executable name.

Copy an existing JSON file, give it a unique lowercase hyphenated slug, and set
`status` to `draft`. Add a specific title and description, a relevant cover photo,
one related game and hub, source links, and sections with unique anchor IDs.
Every article requires `cover: {src, alt, credit}` and a specific `practice` sentence.
Store a 960px WebP and a 480px `-small.webp` version in `assets/images/learn/`.
The build fails if either cover is missing. Use descriptive alt text and honest image
credits; generated covers are labelled as illustrations, never documentary evidence.
Cards, article headers, social previews and Article schema use that cover automatically.
`order` sets the reading order; mix topics so one category does not fill the first screen.
Each section's `html` is trusted, reviewed editorial HTML; this is not an endpoint
for untrusted submissions. Do not put scripts or personal information in content.

Review the explanation, factual examples and source attribution. Use real bylines
and dates only when available; the initial template does not invent them. A guide
should help a reader do something and end with relevant practice. Avoid multiple
articles that answer the same question.

Set `status` to `published` when the article is ready for the next site release,
run the build, and inspect desktop and narrow-screen layouts. Run
`python3 tools/check-editorial.py` to check destinations and publication states.
Drafts are excluded from generated pages and the sitemap. The source directory
is excluded from the Cloudflare asset upload by `.assetsignore`. Setting a
previously published article to draft removes its generated HTML; for a public
URL that must move, arrange a reviewed redirect instead of silently withdrawing it.

Generated pages contain an identifying comment. Edit the JSON, shared CSS or
generator, not the generated article HTML. The generator only removes retired
article pages carrying its own marker.

The library has lightweight search and topic filters; all articles remain readable
without JavaScript. Articles are in English
to match the current games. No new CMS, account or subscription is required.

Write for a curious reader, not for internal growth targets. Start with a real question,
use concrete examples and vary the structure where the subject needs it. Include one
useful check or activity, then a relevant game; be honest when it is general practice
rather than a quiz specifically about the article. Avoid invented authors, personal
experiences, testimonials, medical benefits and promises about memory or intelligence.
Keep SEO, conversion, retention and monetisation plans in internal notes, never public
headings. Public copy should explain what the visitor can read, play or choose.
