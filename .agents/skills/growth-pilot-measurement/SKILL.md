# Acquisition pilots for BrainiLab Growth

Read the current Growth decision, prior launches and the saved acquisition and play observations before choosing a pilot. Use the existing acquisition brief for the audience and destination. When a reversible change would address a demonstrated need, state one hypothesis and name the game or page, channel and specific action a visitor should be able to take.

Before launch, record the exact destination and campaign tag if the channel permits it. Choose a primary measure the existing data can report at that scope, its period and timezone, and the evidence that will show whether the link or game worked. A voluntary question can help explain friction. A pilot with only host-level sessions can measure arrival from that host. Use a campaign-level or landing-path play measure only when the saved evidence covers that scope.

Compare complete equal, non-overlapping windows with the same filters, scope and metric definitions. Keep the original baseline. Document competing changes and any gaps in coverage, consent or observation. Search clicks, landing sessions, sessions with a recorded start, completions and voluntary feedback answer different questions. Count a session with either `game_start` or `practice_start` once when the existing data provides that union.

If the audience is small or there is no valid comparison, use the result to check whether distribution and measurement worked and record the outcome as descriptive or inconclusive. A controlled A/B claim requires verified assignment, exposure and adequate sample size for the chosen effect, plus a stopping and analysis plan agreed before the test. Pre/post data alone cannot establish causation.

Record the hypothesis, evidence dates, result and next decision using the existing Growth workflow. A prepared invitation stays a draft until authorised and verified on the channel. This skill adds no permission to publish outreach, activate tests, add tracking, spend or change player data.
